# Thought Engineer

Living with the AI mind virus.

Architecting AI & software tools for humans in phases: models, code, SQL/Redis, diagnostics, PII safety.

---

## What Thought Engineering Is

Architecting in phases. Each phase of a problem is matched to the right tool, tried against alternatives, and measured, so the outcome is accurate and the deliverable is something a person can use.

## The Work

- **Prompts & system prompts:** writing, tweaking, and tuning them until outputs are accurate
- **Model selection:** trying different models and adjusting them for the job
- **Telemetry & measurement:** measuring results so decisions are backed by data
- **Tool building:** AI tools and software tools for humans
- **Deliverables:** generating outputs people can actually use

## Toolbox

| Layer | Used for |

| SQL | Durable, structured data |
| Redis | Fast state and caching |

## Design Principles

- **Modular design:** each part does one job and can be understood, replaced, or improved on its own
- **Good defaults:** everything works sensibly out of the box, with no setup required to get started
- **Configurable escape hatches:** every default can be overridden, so any module can be pulled out and run alone
- **Isolation testing:** escape hatches make it possible to test a module by itself, without the rest of the system around it

## Practices

- **Migrations:** changes to schemas and data are planned and handled as deliberate steps, not ad hoc edits
- **Diagnostics:** doctor-style integrity checks on modules
- **PII safety:** data integrity and protection of personal data
- **Documentation:** written down so it can be followed
- **Project planning:** work broken into phases before it is built
